# 统一 Agent 开发版验收记录

日期为 2026-11-05。版本保持 2.3.3。用户确认新 PPT 默认使用模板管线，同时明确要求本轮不打包、不发布。

## 本轮交付

- 原生工具公共执行入口、能力版本、同步/任务/工作流分类、执行前后钩子和操作持久记录。
- PPT 接入通用运行与阶段记录，按会话隔离、输入/版本绑定、取消后阻止旧执行器回写、按原运行续做。旧检查点保持兼容。
- 持久化渠道协议证据，配置或模型变化后不继承旧限制。`tool_choice` 拒绝不再误伤整个工具调用。
- 模型设置里的能力检测入口，只有用户点击时发出最多三个虚构协议请求。
- PPT 内容审校受影响页的有界纠正及复审，精简页/问题页单独补做，保留正文配图。
- 显式 WPS 截图视觉审校、受限几何修补和复查，完成后另存版本。原文件不覆盖。
- 修复 WPS 加载项固定后端来源及跨端口能力读取问题。跨域范围仅限持令牌的 WPS 预览读取接口。
- 新制作任务默认使用模板管线，旧任务仍按保存的引擎恢复，可用环境变量回退旧管线。
- 文档工具对模型常见参数别名做有限归一化（`to:"PPT"`、短文件 ID、`text` 对象、多余 `lines`、颜色 `#`），并允许 PPT 参数校验失败后修正一次；执行失败仍禁止自行换源重试。
- 助手正文中的会话文件 ID 链接改为直接下载；文件修改失败后不再让模型把“已完成”留在最终回复，必要时追加事实更正。
- 原生图片任务完成后，把一张生成的缩略图回灌给支持视觉的大脑；不支持图片时自动降级并关闭该会话看图，避免助手凭空描述自己没看到的画面。
- 单张原生改图也按默认策略直接提交；多张仍合并确认，底图不明确时先询问。
- 生图确认策略移到设置页，作为全局默认同步到现有会话；输入框移除“选择素材”和策略下拉。
- 图片参数按模型白名单过滤：gpt-image 系不再发送 `negative_prompt`，表单草稿按渠道/模型隔离。
- 新增 gpt-image-2.6-flare / sunburst 及 -c 模板；gpt-image-2.6 的 edits 请求支持 `output_format:"gif"`，保存与下载保留 `.gif`。
- 文档目录接入设置并记录每份文件的 `base_dir`；同一作品按 family/version 关联，自动保留最近 3 个版本和根文件。
- 压缩上下文增加程序维护的当前计划、文件版本、待确认操作和未完成 PPT 状态；超过预算且只剩少量轮次时，动态保留最近 3 轮而不是固定 8 轮。
- `view_images` 与自动回灌支持动图 GIF：服务端用 omggif 逐帧解码并按 disposal 合成，最多抽 6 帧（多图时每张 2 帧）附给视觉模型，同时标注总帧数、时长和抽样时间；只有 1 帧时明确标注“静态图，不会动”，避免模型凭空描述动画。
- 用本机已生成的一张 `gpt-image-2.6` GIF 验证：512×512、9 帧、1.8 秒，首尾帧存在明显像素差异，确实是动画。旧看图链路只把第一帧交给模型，才导致“GIF 只有一帧、不会动”的错误结论；现在同一张图会附 6 个抽样帧。
- 图片生成、视频生成、音乐生成、语音生成四个页面的参数下拉统一换成自绘 `SelectMenu`，尺寸选项保留“方形 / 横向 / 纵向”分组，不再弹出系统绘制的灰色列表。

## 真实渠道记录

以下只使用脚本创建的虚构培训资料、几何图片及其截图，没有使用用户的文档或图片。结果属于指定配置下的冒烟验收，不能外推为所有模型与复杂资料均通过。

| 场景 | 结果 | 用量与范围 |
| --- | --- | --- |
| 新管线，十章资料 | 11 页，十章及十组示例指标全部覆盖，无精简页，无未解决内容审校问题 | DeepSeek，7 次调用，25,809 tokens |
| 新管线，十八章资料，含内容纠正 | 19 页，十八章和十八组示例指标全部覆盖，修正第 5、6、7 页，复审无剩余问题 | DeepSeek，12 次调用，57,256 tokens。审校标为部分审校，未声称完整通读所有内容 |
| 旧管线，同类十章资料 | 在预算内未交付，保留失败报告 | DeepSeek，7 次调用，91,066 tokens。预算为 80,000，一次在途请求使实际用量超限，随后停止 |
| WPS 原生渲染 | 虚构三页与新管线十九页均成功导出 PNG，抽看渲染截图 | 本机 WPS，未提交模型请求 |
| 真实视觉审阅 | 前三页均被模型观察，未报告明显版式问题 | GPT-6.1-sol，3 次调用，21,616 tokens。其余页面未声称通过模型视觉审阅 |
| 原生改图 | 几何图浅灰背景改为浅蓝，确认前零付费任务，确认后仅一个成功任务，重复确认 409，生成历史可见 | DeepSeek + Gemini，输入为脚本生成的红色方块图。此项验证功能链路，不代表像素级保真 |
| 原生工具协议 | 单调用、多调用、流式、指定工具及嵌套参数通过 | 默认 DeepSeek 渠道，3 次探测，总计 1,171 tokens，未执行探测工具 |

PPT 原始模型输出、用量与结构指标保存在 `artifacts/presentation-eval/`。WPS PNG 在 `artifacts/wps-verification/`，模型视觉报告在 `artifacts/visual-evaluation/`，原生改图记录在 `artifacts/native-edit-eval/`。这些本地产物由 Git 忽略。

## 可重复命令

```powershell
# 全量本地回归与生产构建
npm test
npm run build

# 不联网的固定十章测试
npm run eval:ppt

# 显式联网，仅发送虚构资料，按已配置渠道计费
npm run eval:ppt -- --real --engine template --chapters 18 --max-calls 20 --max-tokens 80000
npm run eval:ppt -- --real --engine both --chapters 10 --max-calls 20 --max-tokens 80000

# 本机 WPS 的三页合成资料检查
npm run eval:wps

# 对评测目录中的虚构文件进行前三页真实视觉审阅
npm run eval:visual -- --file artifacts/presentation-eval/<本次目录>/template-1.pptx

# 一次真实原生改图，输入仅为脚本生成的几何图
npm run eval:edit
```

评测每个引擎分别计算调用和 token 预算。报告区分结构完整、内容审校、实际截图和人工检查，不把文件能打开等同于设计质量已通过。离线模式使用固定返回，不作为真实模型质量证据。
