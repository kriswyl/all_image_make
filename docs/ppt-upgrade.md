# PPT 元素级制作与修改

## 当前结构

- 普通聊天 `doc_convert`：用户要求存为契约（页数 / 必需内容 / 风格）→ 完整原文分批阅读 → 全局叙事规划 → 页面设计 → 批次内容审校 → 整套可见正文审校 → 元素/素材/容量校验 → WPS 渲染与视觉修补 → OOXML 核验 → 候选文件 → 发布。
- 契约由 `presentation-spec-store.ts` 维护，revision 不可变，文件版本绑定具体 revision；改稿沿用同一份要求。
- 创作助手不再提供旧的 PPT 读取/导出工具，制作、转换或修改 PPT 时引导在同一对话切换到「普通聊天」，附件继续可用。服务端拦截历史调用、批量调用及确认后重放；历史生成文件仍可下载。手动「按原结构导出」仍是独立的规则拆页功能，不代表 AI 制作流程。
- 不引入 Agent 框架、Python 或 LibreOffice。现有 WPS 加载项仍是实际渲染依赖，没有渲染器或未启用视觉时明确报告未验证。

## 页面表示

`presentation-elements.ts` 定义 13.333333 × 7.5 英寸画布、稳定元素 ID、Zod schema 和原生 OOXML 渲染。

支持 text/image/shape/icon/table/chart/connector，图片只引用已提供的素材索引；表格、图表数据可在 Office 中编辑，连线以元素 ID 引用端点。支持 row/column + flex/gap 的嵌套布局，编译为同一元素列表。每页最多160元素、整套最多200页。

元素页优先，不能同时提供 box 与 elements。标题元数据不会自动覆盖元素标题，规划器要求标题实际出现在可见文字中。旧 layout 字段保留为兼容元数据。

模板层提供 **10 种版式**：`bullets / cards / comparison / process / table / chart / image / kpi / timeline / quote`，以及 **4 套主题**（`blue / magazine / mono / warm`）。主题只描述配色、字体、留白与装饰，坐标仍由确定性渲染器计算；模型永远不输出 x/y/w/h。

容量处理固定为四层：缩字号（有下限，标题 20pt / 正文 15pt）→ 行高按需分配（条目少、纵向有余量时）→ 按分句压缩 → 截断。每次降级都写进报告 `capacity`，截断页在文件卡点名，原文保留在演讲备注。不依赖无限缩字掩盖排版问题。

## 修改与持久化

普通聊天生成的 PPTX 内包含 `chatcanvas/presentation.json`，保存经过校验的源方案和媒体引用，不重复保存 base64 图片。Office 打开及显示不依赖该文件，但外部软件另存后可能移除此额外文件；缺失时明确拒绝声称能够保真修改。

`doc_read` 分页返回源方案、元素 ID、图片索引和 SHA-256。`doc_edit` 使用版本号创建新版本，保留原件；未指定的新页面备注和来源默认继承。修改有两条通道：

1. **整页声明式**：`pages:[{page, content}]` 只给版式与文字，坐标由渲染器按这份文件报告里的主题算；`appendSlides` 增加页面、`order` 调整顺序、`design` 改主题。渲染器生成的页不允许再被整页元素覆盖（`slide` 通道仅作遗留，且计入报告的 `freeformPages`）。
2. **对象级原位补丁**：`objects:[{slide, elementId, ...}]`，不重新渲染整稿，只改目标部件。支持文本框文字 / 字号 / 颜色 / 位置尺寸、图片替换（新增媒体与关系）、图表显示数据（同时同步内嵌工作簿）、表格单元格文字与增删行列。定位靠导出后的 `cNvPr` 名称（`presentation-object-map.ts`），同名多份、子对象缺失、文件被外部改过都直接拒绝；补丁后逐部件比哈希，只允许预计算的部件变化（目标页、该页 rels、新媒体、必要时 Content_Types）。

该能力面向本应用生成文件，外部 PPTX 目前只作为风格参考。

上传 PPTX 参考通过现有文档附件入口，提取主题颜色和字体，读取原尺寸作提示；输出维持16:9，不复制母版、动画或复杂版式。用户可通过 doc_convert 的 referenceFileId/design 选择参考。

## 核验与修补

- 预检：有限数字、边界、唯一 ID、图片索引、连线端点、表格列数、图表分类/数据长度、文本容量与文本框重叠。
- 容量诊断：生成、单页补做、`doc_edit` 三条入口共用 `shared/presentation-capacity.ts`；截断与换排分开记，溢出不等于内容缺失，但页面不会被标成「内容完整」。
- 对象补丁：改文字变长时只警告不缩字号；换图与改图表会记录实际变化的部件，`[Content_Types].xml` 只补声明、不改已有声明。
- 内容审校：对照原文检查可见事实和限定条件，来源编号覆盖仅作为机械检查；原文附在备注中供追踪，不能替代正文完整性。
- 视觉修补：最多3次实际渲染审阅、2次修补；按ID移动/调整大小/字号/样式，不改文字和数据。每页每轮最多8个补丁、同ID一次、位移±0.5英寸、尺寸变化1英寸、字号变化4pt，下限12pt。非法补丁整体拒绝；每次重新生成、核验、渲染和复查。
- 视觉问题未消失时报告具体页和问题；模型审阅不能保证语义或审美判断正确。
- OOXML 核验检查页数、文本、图表缓存、素材关系、边界及来源备注。截图有变化不等于修复成功，须结合再次审阅和几何检查。

## 已知边界

没有任意外部 PPT 原位保真编辑；图标为内置矢量子集；目前不生成无依据数据，不重建导图原布局。参考封面截图可由会话视觉模型理解，但主题提取入口仅解析 PPTX 主题。超过当前修补能力的问题会明确留待人工或下一轮页面重设计。

对象级补丁的已知边界：图表会同时改写显示缓存与内嵌工作簿（单元格、字符串池、表列名），结构异常时同步失败并明确提示；表格可增删行列（总高/总宽均分，外框不变），但不支持合并单元格与改列宽；图标与连线不支持单点修改；图片只换媒体，不改裁剪/填充方式。整页依赖闭包（整页替换、母版/版式关系迁移）未实现。

## 逐页任务流程（开发版）

普通聊天的内部阅读、全局策划、页面目录、单页设计与审校使用同一套结构化协议；支持工具的渠道发送 submit_presentation_result Function Calling，不支持时明确提示文本兼容路径，仍校验输出。垂直居中的 center/mid 自动归一为 middle，未知值继续拒绝。

材料批次先拆出逻辑页面目录，再逐页设计和审校，页面成功后保存独立断点。内容审校区分 error 与 suggestion，建议不阻断；最终审校定位到页后最多两次定点修复并复查，原始来源和备注保留。已有批次来源覆盖检查继续执行。

PPT 阅读、策划与内容修补在单轮共享80次调用和200000 tokens上限，并受会话总调用、时长和token预算共同约束。token上限依赖渠道返回用量，单次正在进行的请求可能超过剩余额度。视觉渲染仍有原来的最多三轮限制，并受会话预算约束。断点重用要求资料、用户要求、模型和对应阶段输入一致；换资料或改目标会重新规划。
