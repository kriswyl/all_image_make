# 普通聊天 Agent 能力路线

目标是在同一对话中根据用户意图选择工具、持续执行并核验结果；工具和运行时应与文档格式解耦。普通聊天仍可直接回答，复杂任务可使用 `plan_update` 维护步骤。

## 当前基础

- 原生工具调用由模型驱动，注册表将工具的描述、执行和去重策略组合在一起；现有文档工具通过适配器接入。
- 工具往返、模型调用次数、处理时长和可选 token 上限可在普通聊天的上下文设置中调整；每次最多 8 个调用，顺序执行。token 按渠道返回的输入输出用量在每次调用后检查，可能超过上限；未返回完整用量时停止后续调用，费用仍不能据此精确推算。
- 只在一批工具全部结束、准备再次请求模型时保存安全断点；异常重启后，在模型、渠道配置和工具定义未改变的前提下从断点继续。恢复保留轮次、时间、用量和已完成的创建操作记录；正在执行或状态不明的工具不会自动重放，超大断点不会保存。
- 重启时，已发布并登记的本地生成文件会根据操作 ID 恢复到工具卡；其他进行中的原生工具调用标为中断，提示副作用可能已经发生。PPT 分批规划可在相同模型、素材和意图下通过重新发起转换复用已审校的批次。
- 较早的分页读取结果在本轮上下文过大时移除，保留文件 ID 和偏移量供按需重读；会话历史仍通过已有摘要机制管理。
- 产物位于会话文档目录；读取和删除仍受会话范围约束，删除需用户确认。
- 文本类文档支持分段读取、精确文字搜索和基于内容哈希的精确替换，修改结果保存为新文件。Office 已支持 Word 正文替换、字符样式、段落样式（对齐/行距/段前后/缩进）与表格增删行列、Excel 单元格读写、批量标记与「含图表工作簿的保留式改数」（图表缓存同步）；PPT 走「整页声明式 + 对象级原位补丁」（文字/样式/换图/图表/表格），但外部 PPT 保真编辑仍未实现。
- PPT 在完整分批阅读后依据阅读摘要做全局策划，随后逐批设计与内容审校；支持稳定ID元素、行列约束布局、原生表格图表和连线。保留来源备注并核对整套可见正文；阅读摘要和模型审校不能保证语义完全正确。
- WPS 加载项提供实际渲染，使用只读临时副本。启用看图时逐页审阅，按元素ID修补几何与样式，最多3轮渲染、2次修补，保留文字与数据；失败与剩余问题明确报告。生成的PPT保留源方案，支持整页重做（10 种版式、4 套主题）与对象级原位补丁（文字/样式/换图/图表/表格），补丁后逐部件比哈希。外部PPT仅支持颜色字体参考；整页依赖闭包与备用渲染器仍待实现。详见 [PPT改造](ppt-upgrade.md) 与 [项目框架](architecture.md)。

## 后续能力，按依赖顺序

1. **长任务运行时**：继续完善更细粒度的工具中断恢复、外部服务幂等、精确费用预算和跨进程异常评测；安全断点不覆盖工具执行中的崩溃，也不对未登记的外部副作用作推断。
2. **工作区工具**：在受限工作区提供列目录、分段读写和精确编辑，处理符号链接、并发修改和文件大小限制；产生副作用的操作定义权限策略与审计记录。
3. **检索与外部能力**：增加带来源的网页搜索、抓取、文件索引和检索；网络访问需要防范内网访问与提示注入，外部内容始终视为数据。
4. **安全执行环境**：仅在隔离环境可用时提供代码执行和依赖管理；限制网络、资源和运行时间，明确用户授权及结果回收。不能把宿主机任意命令伪装成沙箱。
5. **领域工具包**：文档、画布、图片、音视频等以各自工具包注册，按任务和模型能力选择；文档处理需要结构化读取、逐段修改、格式保真能力声明和真实文件核验。
6. **质量闭环**：PPT 已具备元素级生成、真实渲染、自动逐页视觉检查与有限修补。继续扩展真实复杂样本评测、备用渲染器、重设计能力和外部格式保真编辑，并告知解析损失；模型审校不能保证语义正确。
7. **评测与扩展**：用真实多步任务、故障注入、重启恢复及安全边界测试评测；之后再考虑 MCP、技能包和多 Agent，保持权限和上下文隔离。

目前计划工具只记录模型提交的步骤，不能保证模型执行或验证了步骤；计划本身不会改善 PPT 渲染，也不会为程序增加网页搜索、代码执行或通用 Office 编辑能力。
