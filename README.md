一个面向**图片 / 视频 / 音乐生成中转 API** 的本地客户端，附带 Tauri 桌面版。前端负责渠道配置、参数输入、结果与历史查看；后端统一处理鉴权、协议适配、异步轮询、素材落盘与脱敏诊断。

> 品牌名是 **ChatCanvas / 语布**，`productName` 从 2.2.1 起也改成了 `ChatCanvas`。数据目录由 bundle identifier（`com.imagerelay.studio`）决定，改名不受影响；2.2.0 及更早的安装叫 `ezcanvas`，升级到 2.2.1 后会有一次新旧两套安装并存，手动卸载旧的 `ezcanvas` 即可。

## 功能

### 生图

- OpenAI Images、OpenAI Chat Image、Gemini Content、Generic JSON 和 Midjourney 五种适配器
- 文生图与最多 8 张参考图图生图，支持 PNG、JPEG、WebP（单张最大 10 MB）
- 参考图可以点击选择，也可以直接把图片文件拖到上传区
- 选中参考图后，OpenAI Images 自动从 `/v1/images/generations` 切换到 `/v1/images/edits` 并改发 multipart
- **Midjourney**：有参考图自动走图生图接口，否则走 `mj_imagine`；`mj_edits` 不再作为可选模型展示。参数面板可以直接选画面比例、模型版本和排除内容（对应 `--ar` / `--v` / `--no`）。结果四宫格下方只显示能直接执行的放大/变体/重绘按钮，全部中文，**生图工作台和对话创作里都能点**，点一下提交后续动作并继续轮询
- 官方风格参数与高级 JSON 参数透传
- URL / Base64 结果下载并保存到本地

### 视频

四种视频渠道，各自按官方协议构造请求体：

| 渠道 | 适配器 | 模型 | 时长 | 分辨率 | 参考图 | 音频 |
|---|---|---|---|---|---|---|
| 通义万相 | `wan-video` | `wan3.0-video` | 2–30 秒 | 480P / 720P / 1080P | ≤ 10 张 | ✓ |
| Grok Imagine | `grok-video` | `grok-imagine-video`、`-1.5-preview`、`-1.5` | 1–15 秒 | 480p / 720p / 1080p | ≤ 7 张 | — |
| 豆包 Seedance | `seedance-video` | `sd-2.5`、`sd-2.0`、`sd-2.0-fast`、`sd-2.0-mini` | 4–30 秒 | 480p / 720p / 1080p | ≤ 10 张 | ✓ |
| 快手可灵 | `kling-video` | `kling-3.0`、`kling-3.0-turbo`、`kling-3.0-omni` | 3–15 秒 | 720p / 1080p / 4k（运动控制到 1080p） | Omni ≤ 4 张 | ✓ |

生成模式按渠道给出，切换模式会清空已传图片：

- **万相 7 种**：文生视频、首帧生视频、首尾帧生视频、参考生视频、视频编辑、视频延长、参考文件生视频
- **Seedance 4 种**：文生视频、首帧生视频、首尾帧生视频、参考生视频
- **Grok** 没有模式概念，只按「有没有参考图」区分

万相的参考视频 / 音频 / 文档只接受公网 URL，不支持上传；图片一律转为内联 data URI 发送。提交后进入异步轮询，完成后自动下载视频落盘，支持双击放大与历史回看。

视频任务提交后会记下上游的任务 ID。**应用重启时，已经提交出去、还在生成的视频会接着轮询**，而不是被判定为失败。

参考图同样支持拖放上传，交互与生图工作台一致。

### 音乐

词元流墟的 Suno 音乐渠道（`suno-music`，模型 `suno_damobi_music`）：

- **一次固定生成 2 首**，支持灵感描述、自定义歌词、纯音乐、翻唱、混音、音效、歌单风格、取样（歌词生成暂不接）
- 翻唱 / 混音可以从历史歌曲里选源曲；音效可以设置 BPM、调性和是否循环
- 自定义模式要填曲风；歌名、排除曲风可选，歌词最多 5000 字
- 异步提交后轮询 `/api/midjourney/drawInfo4`，成功后把两首音频和封面一起落盘
- 历史页有独立的「音频」筛选；结果可以直接播放、下载、删除，歌词可以展开查看
- 对话里的 `generate_music` 也会一次返回两首，工具卡片里逐首播放；音乐不进画布

协议细节和踩坑记录见 [`SUNO_HANDOFF.md`](SUNO_HANDOFF.md)。

### 语音

词元流墟的 Gemini TTS 渠道（`gemini-tts`）：

- 模型：`gemini-3.8-flash-tts`、`gemini-3.8-flash-lite-tts`、`gemini-3.1-flash-tts-preview`
- 30 个预置音色；支持单人配音和双人对话（正文用 `A：` / `B：` 标注）
- 风格/情绪通过 `annotations` 控制，不会读进正文；可选 BCP-47 语种
- 输出 24kHz / 16bit / 单声道 WAV；3.1 preview 返回的裸 PCM 会在服务端补 WAV 头
- 独立「语音生成」工作台；历史页的音频筛选同时包含音乐和配音
- 对话里的 `generate_speech` 可以直接朗读脚本、旁白或双人台词

没有音色克隆、SSML、变速；一次提交一段文本，超长内容建议按 50–200 字分段生成。协议细节和实测坑见 [`TTS_HANDOFF.md`](TTS_HANDOFF.md)。

### 对话创作（Agent）

一句话描述需求，助手自己决定画图、改图、优化提示词、接着上一张生成视频，还是写一首歌。

- 「画一只戴草帽的橘猫，水彩风」——它从可用渠道里自己挑模型，不用你选
- 「把它手里的东西换成咖啡杯」——看着当前画布那张图改，不是盲改
- 「刚才那张做成 5 秒视频，镜头慢慢推近」——接着上一张往下走
- 「写一首关于雨后城市的温暖民谣」——自己决定灵感模式还是自定义歌词，一次出两首
- 「把这段旁白读一下，温柔一点」——用 `generate_speech` 配音，支持指定音色和双人对话
- 支持流式输出；推理模型（如 `deepseek`）的思考过程单独显示在一个可折叠面板里

大脑走标准 chat completions 协议，在「渠道配置」里加一个**对话渠道**即可（内置预设「词元流墟-对话模型」）。它是普通的第二类渠道，和生图 / 视频渠道互不影响。

几个刻意的设计：

- **助手看不到真实模型 ID 和渠道 ID**，只看到 `gemini` / `wan` / `seedance-2.5` 这类带版本号的简称，由服务端解析成真实配置。这样它不会编造出不存在的模型名，你也不用把密钥信息交给它
- **画布是「这一轮要带的图」（最多 8 张）**：新生成的图只进素材库，不自动占用画布。选中的图直接排在输入框附件区（和本地待发图同一排），**① 首帧 / ② 尾帧 / ③ 参考**直接标出来，左键看大图、右键设首帧 / 尾帧；画布为空时这一排完全不出现。发送时画布图和拖进输入框的图会一起写进这条消息并在对话里显示，**发完自动清空画布**
- **视频确认可以关**：默认只在「自动续跑」时才问一句，卡片上能直接改时长 / 分辨率 / 音频，改完随确认一起提交
- **音乐同样只在自动续跑时确认**：用户明确要一首歌就直接提交；一次固定两首，确认卡片会写明费用
- **可以随时打断**；生图已经发出去的情况下，助手会告诉你图还在后台画，画完会进「生成历史」，不必重新生成
- **一次可以并行提交多个生成任务**（最多 8 个）：说「跑三张不同风格」时同时发出去，超过上限的会如实说明有几个没提交
- **对话里可以直接上传图片**（按钮或拖拽）：上传的图立刻能当画布、有缩略图，但不进「生成历史」、不占会话任务额度
- **脚本可以直接传 `.txt` / `.md`**：助手读完全文后拆成会话内分镜表，每镜保留剧本原文、画面描述、台词、景别、运镜、音效、时长和视频提示词。先看表、手动润色，再在面板里生成分镜图；图确认后用每镜分镜图做首帧生成视频，台词可以再单独生成配音。每次最多提交 8 镜，确认框会写明这次要花几笔任务，失败或不满意的镜头可以单独重跑
- **角色 / 场景设定图**：助手拆镜时给每镜标出场角色和场景，也可以点「标注角色/场景」让助手给已有分镜补标签（不重新拆分、不动已生成的图）。分镜面板是大浮层：左侧每个角色和场景有独立的设定卡，可以生成、上传或选本会话已有图，确认后才会被用于分镜；设定栏可拖动调宽，也能收成窄轨，全部确认后会自动让位给分镜。右侧镜头表按「角色 A + 角色 B + 场景」带对应的多张参考图，人物和空间不会互相串。角色、场景和分镜结果都能点开看大图，已完成镜头可以勾选批量重跑
- **镜头图画布**：分镜工作台可以切到「画布」，把同一份分镜投影成镜头图——脚本、角色 / 场景设定和每一镜按叙事顺序排开，角色 / 场景用不同类型和颜色的连线指向引用它们的镜头。镜头节点显示首帧缩略图、描述、台词和图片 / 视频 / 配音状态；节点可以拖动并保存位置，也能一键恢复自动布局。从角色 / 场景节点拖线到镜头即可添加引用，点引用标签可以断开。选中镜头（Shift / Ctrl 多选）后，顶部工具条直接生成图片或视频；右侧设置可以切换首帧 / 首尾帧 / 参考图，从本会话素材里换首帧、选尾帧、加参考图，设置随镜头落库，不支持的输入方式会明确说明或禁用生成
- **产物节点、尾帧续写与按场分组**：分镜图、视频、配音会拆成镜头下方的独立节点，render / 首帧 / 尾帧 / 参考 / 续写用不同颜色和虚实连线。图片节点可以直接拖到镜头，选择设为首帧、尾帧或参考图；视频节点有「尾帧续写」，在浏览器里截取最后一帧后静默创建一个带父镜头关系的新镜头，不自动提交生成。画布还能按场景把镜头排成不同行，每行带场景框和镜数标签；分组只是布局视图，关闭后恢复手动位置
- **成片导出**：按镜号顺序拼接已生成的视频，每镜配音从该镜开头混入，可选混入视频原生音频；720p / 1080p、30fps，支持进度和取消。导出用 canvas + Web Audio + MediaRecorder 实时合成，不额外捆绑 ffmpeg；浏览器支持时优先 MP4，否则自动 WebM，保存走桌面保存对话框或浏览器下载。当前不做转场、字幕、背景音乐和静帧补镜
- **全局默认生图 / 生视频 / 音乐 / 语音模型**：在「模型」面板里按类型切换，点一下卡片就设为默认；音乐（Suno）和语音（TTS）各自一份默认值，改一个不会影响另一个。大脑没点名时用它，你在对话里点名的仍以你为准
- 图片先挂在输入框上，**发送时才真正上传**；空会话会按第一条消息自动命名
- 助手能做的事只有生成、改图和维护画布，**没有清空历史 / 改渠道配置这类破坏性能力**

### 通用

- 多渠道、多模型 ID 配置，一个渠道一个密钥
- **添加渠道向导**：内置 11 个站点预设，按模型系列分别创建渠道，每个单元使用独立密钥，并在卡片上显示站点品牌图标
- SQLite 历史记录、结果缩略图与脱敏请求诊断
- API Key 从环境变量读取，或保存在数据目录的本地文件中供下次启动使用
- 可调生成超时（10 秒到 30 分钟，默认 3 分钟）
- 默认阻止本地和内网目标地址，可按渠道显式放开

### 历史与素材目录

- 历史列表每一行都有勾选框，表头可以全选当前筛选下的记录，勾中后顶部出现「已选 N 条」的操作条，可以**批量删除**自己挑出来的那几条
- **清空历史**前会弹确认框，可以选择「同时删除本地文件」（默认）或「仅删除记录，保留本地文件」，并按图片 / 视频 / 全部筛选；批量删除走的是同一个确认框
- 生成产物的保存目录可以改成任意位置（历史页的「目录设置」，桌面版使用原生文件夹选择器），也可以一键恢复默认
- 换目录**不会迁移已有文件**：每条产物记录着自己所在的目录，旧历史缩略图、播放和下载都不受影响
- 视频任务的诊断记录采用「首尾完整 + 中间精简」——提交请求和最后一次轮询保留完整响应，中间的轮询只存一行状态摘要，避免一个任务把数据库撑到几 MB

### 内置站点预设

| 站点 | 预设单元 |
|---|---|
| 向量引擎 `api.vectorengine.cn` | gpt 生图、gpt-c 生图、gemini 生图 |
| 词元流墟 `api.tiantoken.com` | gpt 生图、gpt-c 生图、gemini 生图、Midjourney、万相视频、grok 视频、seedance 视频、可灵视频、Suno 音乐、Gemini 语音、对话模型 |

中转站通常按模型系列分别售卖密钥，因此这些单元互不共用 Key。也可以选择「自定义配置」手动填写任意 Base URL。

## 界面

界面按 Codex 桌面版重做，全部使用黑白灰配色（强调色就是黑色）：

- **自绘标题栏**（`decorations: false`）：最小化 / 最大化 / 关闭和窗口拖拽区由应用自己画，侧栏开关在左上角
- **侧栏外壳**：对话创作、图片生成、视频生成、音乐生成、语音生成、历史记录、模型设置七个入口；会话列表独立滚动，不会被长列表挤出视野
- **侧栏可拖拽调宽**（190–420px），`Ctrl+B` 收起 / 展开，宽度记在 localStorage
- **模型与渠道选择器带厂商 / 站点图标**，选完直接显示在输入框上方
- **composer 下方有 token 账本**：当前上下文占用 + 本会话的输入 / 输出用量
- **画布条默认收起**，需要时从会话头部的「画布 N」展开；点击缩略图即可加入 / 移出画布
- 字体为拉丁 Inter + 中文 Noto Sans SC；等宽字体只用于真正的代码 / 数据框

工作区：**图片生成**、**视频生成**、**音乐生成**、**语音生成**、**对话创作**、**模型设置**、**历史记录**。图片、视频、音乐、语音工作台共用顶部的渠道 / 模型选择器和右侧结果区；对话创作是左侧会话列表 + 右侧消息流的对话式界面；模型设置页管理渠道并执行连接测试；历史记录页汇总全部任务与产物，并能按类型清空历史、更改产物保存目录。

## Tauri 桌面版

桌面版保留现有 React 界面，并由 Tauri 启动内置 Node.js sidecar 提供本地 API。开发模式：

```powershell
$env:Path = "$env:USERPROFILE\.cargo\bin;$env:Path"
npm run tauri:dev
```

构建可直接运行的 release 版本：

```powershell
$env:Path = "$env:USERPROFILE\.cargo\bin;$env:Path"
npm run tauri:build:exe
```

主程序位于 `src-tauri/target/release/image_relay_studio.exe`。直接分发时必须同时保留同目录的 `node.exe` 与 `resources/`；正常分发建议使用 `npm run tauri:build` 生成 NSIS 安装包。第一次构建需要 Rust、Visual Studio C++ Build Tools 和 WebView2；NSIS 首次打包还需要能够访问 GitHub 下载 Tauri 官方工具。

`npm run tauri:build` 会产出自动更新签名（`setup.exe.sig`），因此需要本机存在 `%USERPROFILE%\.tauri\chatcanvas-updater.key`；找不到时构建会直接报错并给出生成命令。只打便携版用 `npm run tauri:build:exe`，不需要私钥。`npm run release:installer` 是“测试 + 打包 + 整理产物”的组合命令。

将当前 release 产物整理为便携目录和 ZIP：

```powershell
npm run tauri:package:portable
```

输出位于 `artifacts/chatcanvas-v2.2.5-portable-win-x64.zip`。

桌面版 API 固定监听 `127.0.0.1:17892`。SQLite、参考图与生成产物默认保存在 `%APPDATA%/com.imagerelay.studio/data`，运行日志保存在 `%LOCALAPPDATA%/com.imagerelay.studio/logs`。生成产物（图片和视频）的目录可以在历史页改成任意位置，改完只影响之后生成的文件。

## 自动更新

**Windows 安装版**支持自动更新：

1. 启动 5 秒后静默检查 `updater` tag 上的 `latest.json`，失败不打扰用户
2. 有新版本时侧栏版本号旁出现圆点，点开可以看到版本号和更新说明
3. 点「下载并安装」后先下载并校验签名；**下载完成才停掉内置后端**，然后安装并自动重启
4. 下载或校验失败时应用继续以当前版本正常运行

**Windows 便携版**（目录里有 `.portable` 标记）只提示新版本并打开下载页，不会自动装成安装版；**macOS 和网页版**也只提示，不自动安装。

更新包使用 minisign 签名，公钥钉在 `src-tauri/tauri.conf.json`，私钥只存在本机 `%USERPROFILE%\.tauri\chatcanvas-updater.key` 和 GitHub Actions secret 中。**私钥丢失后，已安装用户将无法再自动更新**——务必备份，详见 [`PACKAGING.md`](PACKAGING.md#自动更新与发布)。

已经安装了 2.1.x 的用户需要手动安装一次 2.2.x；从 2.2.0 起后续版本可以自动更新。

## 密钥配置

推荐在项目目录的 `.env` 中配置渠道密钥：

```dotenv
PORT=17891
RELAY_API_KEY=replace-me
VECTORENGINE_API_KEY=replace-me
```

添加渠道时，将「环境变量」填写为 `RELAY_API_KEY`。也可以直接在渠道界面输入 API Key，它会以明文 JSON 保存在数据目录的 `channel-keys.json` 中（文件权限 0600），服务重启后自动载入，不需要二次配置。删除渠道会同时删除该渠道的密钥。密钥不会写入 SQLite，也不会显示在诊断记录或接口响应中。

明文保存意味着任何能读取该文件的程序都可以取得密钥。数据目录已在 `.gitignore` 中，请不要提交或随意分享它。

向导预设为每个模型组分配独立的环境变量名，例如向量引擎的 gpt 使用 `VECTORENGINE_API_KEY`、gpt-c 使用 `VECTORENGINE_GPT_C_API_KEY`、gemini 使用 `VECTORENGINE_GEMINI_API_KEY`。

服务也会读取项目上一级目录的 `.env`。可用 `DATA_DIR` 环境变量修改 SQLite、参考图与生成产物目录，默认使用项目内的 `data/`。

## 渠道配置

1. 填写渠道名称、Base URL 和适配器类型。
2. 确认生成路径，留空则使用所选适配器的默认路径。
3. 选择鉴权方式并配置环境变量名或 API Key。
4. 每行填写一个中转站实际使用的模型 ID。
5. 保存后可在渠道页执行连接测试，再到对应工作台提交任务。

基础表单参数会由所选适配器映射到目标协议。高级 JSON 会合并到最终请求体；程序不判断某个渠道是否支持或实际执行了这些参数。最终发送内容和响应可在任务诊断中查看。

## 参数范围

生成页会按适配器显示对应参数，不会维护渠道能力矩阵：

- **OpenAI Images**：常用尺寸与自定义宽高、质量、背景、输出格式、数量、内容审核、风格、响应格式、流式输出
- **Gemini Content**：宽高比、输出尺寸（1K/2K/4K）、候选数量、温度、Top P、Top K、最大输出 Token、响应模态、Seed
- **视频**：生成模式、时长、分辨率、宽高比、参考图、Seed、水印、音频；万相另有提示词智能改写
- **生成超时**：所有适配器通用，10 秒到 30 分钟，默认 3 分钟，保存在本机
- **高级 JSON**：透传协议或中转站专属字段，优先级高于可见控件

OpenAI 的 `style`、`response_format`、`stream` 等字段会按接口原名发送；Gemini 的生成控制会合并到 `generationConfig`，宽高比和尺寸会合并到 `imageConfig`。某个中转渠道是否接受或实际执行参数，仍以该渠道响应为准。

### 内联素材体积上限

视频素材以 base64 data URI 内联发送。部分中转站对请求体有硬上限（实测约在 1–2 MB 之间），超限时只会返回含糊的 502 或连接层失败。客户端会把上传的图片压到长边 1280 的 JPEG 后再发送；服务端也会提前拦截超限的内联素材并给出明确报错，而不是让任务空等。公网 / `oss://` 地址不占请求体。

## 已知限制

- 蒙版编辑、模型能力自动识别、参数是否实际生效的判断不在当前范围内
- 部分中转站的视频模型可用性可能与其模型列表不一致，以实际提交结果为准
- 视频渠道的真实联调覆盖有限，详见 [`VIDEO_HANDOFF.md`](VIDEO_HANDOFF.md)
- 对话创作依赖的「大脑」模型由你自己提供；不同中转站对 JSON 输出和图片输入的支持差异较大，助手的表现会随之波动，详见 [`AGENT_PLAN.md`](AGENT_PLAN.md) §15 的降级路径

对话创作的完整设计（数据模型、工具清单、系统提示词、状态机、护栏）见 [`AGENT_PLAN.md`](AGENT_PLAN.md)；视频协议细节见 [`VIDEO_HANDOFF.md`](VIDEO_HANDOFF.md)；开发交接背景见 [`DEVELOPMENT_HANDOFF.md`](DEVELOPMENT_HANDOFF.md)。
